# 扫描地图标注流程

执行模型策略见 [SKILL.md](../SKILL.md)。本流程产物始终为图面候选，不使用现代边界或生成式补图替代读图。脚本为单写者工作目录，禁止多个标注者同时修改同一 run。

## 准备与坐标

先固定原图、来源/使用条件、目标与排除项；明确完整图幅还是局部任务。下载、准备与绘制分开计时，原图 hash 由 `init` 记录。素材获取受阻时报告障碍，不绕过验证或擅自更换地图。

原图左上像素中心为 `(0,0)`，x 向右、y 向下。`view --bounds` 是整数像素边缘框 `[left,top,right,bottom)`，只控制查看范围，不定义独立分片。视图的 `view_to_original` 提供 x/y 比例和偏移：`original = view * scale + offset`，不得按界面缩略图猜坐标。

`view` 保留 `original.png`，按需加 `enhanced.png`，叠加图为 `overlay.png`。增强默认关闭，模式见下文。优先保留实际可见的原始像素细节；大裁剪缩小后不算精细查看。

## 逐局部提交

**概览定位 → 当前局部读图 → 独立 patch 保存并 apply → 程序 check 与覆盖核对 → 下一局部。** 默认同一标注任务串行完成；禁止先看完所有局部再集中生成初稿，最后直接导出保存版本，不重写整套坐标。

```bash
python3 gis-kit/scripts/raster-annotate.py init /path/map.jpg /tmp/map-run --task '图中行政界；排除道路、河流、文字与经纬网'
python3 gis-kit/scripts/raster-annotate.py view /tmp/map-run --bounds 100 100 900 900 --max-size 1200
# 实际查看原图；模型直接写当前局部 patch（契约见下文链接）
python3 gis-kit/scripts/raster-annotate.py apply /tmp/map-run /tmp/patch-01.json
python3 gis-kit/scripts/raster-annotate.py check /tmp/map-run
# 提交成功后才生成下一局部新视图；重复读图、append、check
python3 gis-kit/scripts/raster-annotate.py normalize /tmp/map-run
python3 gis-kit/scripts/raster-annotate.py export /tmp/map-run
```

- 写坐标时查 [对象与记录契约](raster-schema.md)。首处可用 `draft` 或 `append`，后续新增用 `append`；已有可靠节点/边只引用 ID，禁止重新 put。每次使用最新 revision 和新视图，不预制一批过期视图。
- 当前局部的最小上下文为目标/排除项、原图和映射、当前版本、接入节点及必要邻接边、新 ID 前缀。`summary --ids` 只返回指定对象与依赖；不要加载完整开发历史或所有旧坐标。长任务可由最新版本、待画范围和原图 hash 恢复短上下文。
- 相邻观察区保留可辨重叠，复用已确认接入节点。线未画完时可在清晰处设临时接入节点并记录，不能冒称地理交汇。新支线接到旧边内部需单独拓扑拆边并保持原轨迹，不自动吸附或重复画共享界。
- 概览不要求提交；当前局部可继续放大辨认。无目标或无法判读时记录观察、缺失和待画范围，不制造空版本或强行闭合。提交或记录本处障碍后才切换区域。

调用者负责留存实际查看→patch→返回 revision 的顺序；脚本能保护对象和版本，不能证明模型实际看图或阻止其提前查看多处。自动分片、核心区归属、接缝合并均未实现；下面的登记与调度要求由调用者执行，不代表新增 CLI 能力。

## 完整图幅的节点、分层与覆盖

- 先按图例建立目标类别与面清单：领土外界、内部行政界、共管地等分别核对；颜色相同不表示没有目标边界。分层是语义核对顺序，共用几何只存一次。独立插图单独登记，不能连接到主图线网。
- 当前局部先登记真实交汇、端点和待辨连接，再绘制节点之间的边。几何相交不自动等同语义相连；无交汇闭环、飞地、孔洞及孤立边也必须登记，不能因节点优先漏掉它们。
- 使用分片时明确 core 与观察 halo，坐标统一到原图。跨片处设稳定 ID 的临时延续节点，记录坐标、边界类别、所属边、相邻片、走向与待接状态；这类节点不冒称真实交汇。邻片先看重叠原图并引用同一 ID。位置或连接不符时停下解决冲突，禁止按距离自动吸附；裁剪框不能变成政区边界。
- 可把同一交汇点的若干相连边放在一个 patch。每条边只有一个提交归属，另一个交汇点仅引用；无交汇的组件单独提交。不强制逐边一次调用，也不强制交汇点分组；提交数减少不保证总请求或成本减少。
- 顶点按实际转折和曲率分布，点数/间距预算仅作提示。新增点须重新观察原图后定位；沿原线等距内插不会增加边界证据。形状修订可增、删、移动内部点，保护共享端点；单纯删点无法补回遗漏弯折。
- 每个局部保留已描边、待描边、待闭合面、未接端口和疑义清单。已发现的错接、自交、重复边与明确遗漏须修复或将该处显式置为 hold，禁止把 partial 标成完成。局部阻碍可绕行处理独立区域，但最终必须回收，不能靠扩大查看范围累计完成度。

用户授权并行时，工作者只写独立提案，由单一写者按最新 revision 合入。相邻片收到已确认端口后再画接缝；不要同时独立决定同一接点。可让同一工作者逐处查看、提交并检查数个局部，交接只传源图映射、目标、节点依赖、覆盖状态及必要几何；不以吃满上下文或提高缓存占比作为优化目标。

## 验收与成本口径

任务开始时区分实用制图和精细描摹门槛。明确漏块、漏完整分支、错误连接及改变区域关系的缺陷应阻断相关成果；不影响用途的局部偏移可记录为非阻断。不得降低拓扑要求来迁就像素贴合，也不得把所有小偏移都变成无限返修任务。

独立审核先看原图并成功保存源图目标清单，再看叠加；同时核对全部分片、接缝、插图、类别与面清单。导出遗漏列表只覆盖已声明对象，空列表不能证明全图无遗漏。需要面成果时，面覆盖、共享边闭环、飞地与孔洞必须单独验收。

用户要求成本时分别记录绘制、审核、返修、主调度的墙钟时间与代理执行时间，保留模型请求数、初始提交数及纠错提交数。输入拆为缓存与未缓存，输出单列；缓存输入占比为 cached_input/input，reasoning 为 output 子集。无日志则写未知，不能从总 token 推算套餐窗口实际扣减。并行代理耗时之和不等于任务墙钟时间；历史对照、审核工作量或范围不同须披露。

## 审核、返修与交付

初稿后做一次整体叠加审核，集中看明显遗漏、错误路径和节点问题；不要每追加局部都调用模型自审。只为影响用途的缺陷触发一轮局部修订；明确要求精细试验时最多两轮，无改善则保留疑义。具体操作见下文。

`export` 保存完整标注 JSON、原生曲线 SVG 和 GPKG。GPKG 按指定容差采样贝塞尔，只包含非空点/线图层及已定义、闭合、有效的面；不完整或无效的面列入遗漏清单。面须明确引用共享边，不自动判断区域归属。已有确认线网可另用 [candidates.py](repeated-delivery.md#已确认线网候选组面candidatespy) 生成待审查闭环；它不写回标注或自动采用。SVG 保留原生边/点，面的引用和孔洞定义保存在 JSON。

未配准 GPKG 为未定义 CRS 的像素工程空间，禁止标 EPSG:4326 或冒充标准经纬度 GeoJSON。需地理坐标时另走 [配准](raster-georeferencing.md)，不混合描线误差与配准误差。

交付原图、叠加、版本、导出、未解决项及 [会话记录](raster-schema.md#会话记录)。缺少独立参考时只报告图面贴合、遗漏、错误路径和几何诊断，不报告准确率。渐进提交的精度/净成本收益仍待对照。

## 检查与人工审核

- `check` 检查自交、重叠、异常交叉、越界、重复坐标及面有效性；不能发现全部语义遗漏。`normalize` 仅去除连续重复折线顶点，另存版本，不吸附或平滑。
- `review` 生成疑义局部原图、叠加及冻结邻点的修订窗口；`summary --ids` 限制返回对象。节点可靠时用 shape，连接有误时单独 topology。`repair-candidate --face ID` 只保存 make_valid 候选，不能自动采用或只取最大碎片。
- `review-pack` 按明确 bounds 生成 1–6 处编号对照，不自动寻找全图错误。展示 index.png 及各区原尺寸原图/叠加；蓝色 visible、橙色 uncertain/inferred，加粗线可能遮盖偏差。

```bash
python3 gis-kit/scripts/raster-annotate.py review-pack /tmp/map-run --bounds 100 100 500 400
python3 gis-kit/scripts/raster-annotate.py feedback /tmp/map-run PACK_ID /tmp/feedback.json
```

反馈最小格式：

```json
{"reviewer":"human","decisions":{"R01":{"status":"rejected","note":"转折有误","marked_image":"circled.png"}}}
```

只转录真实人工意见，状态为 accepted/rejected/pending，初始 pending。圈图可选，支持 PNG/JPEG/WebP；相对路径从反馈文件目录解析，副本及 hash 留存。反馈不改几何，接受局部不代表全图正确。截图须对照原视图定位，不能直接当原像素坐标。只返修 reject 区域；改后生成新包，旧反馈保留作依据，不冒充新版本已通过。

## 可选图像辅助

`view/review --preprocess MODE`：none 为默认；gray/autocontrast 可能丢失颜色证据；neutral-ink 抑制彩墨，可能同时压低界线；local-contrast 增强亮度，也可能增强影线；palette-denoise 弱去噪，可能改变细笔画观感。后三者需 NumPy/OpenCV，缺失则报错，不自动安装。

仅在疑难局部生成一个辅助版本，同时查看原图；处理在原分辨率裁剪与 halo 上进行，随后缩放。局部增强随裁剪范围变化，放大不增加原始证据；已有小范围对照未证明温和增强有稳定优势。具体参数查 `--help` 与 `_raster_preprocess.py`，不在文档复制默认数值。

用户明确要求程序追线时才使用独立 `raster-local-trace.py --help`：输出骨架候选及其 hash/参数，不写回主标注。最短路可能走错语义路径；不自动闭合、补边或组面，不能冒称模型原生绘制。
